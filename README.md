# CueFlow · 舞台演出提示链编排

基于 **React + TypeScript + Vite + React Flow** 的舞台演出提示（Cue）链编排工具。
在画布上编排灯光、音效、演员提示节点及其依赖关系，并可为节点指定**舞台资源**
（如追光1、麦克风A）——同一资源上的提示按节点顺序自动串行、不可重叠。
系统自动计算每个提示的 **最早 / 最晚触发时刻、松弛时间** 与整场演出的
**关键路径 / 总时长**，并在画布、运行表、资源队列中同步高亮。

## 功能

- **三类提示节点**：💡 灯光 / 🔊 音效 / 🎭 演员，按类型着色区分
- **依赖连线**：拖动节点手柄即可建立依赖；**自动阻止形成环路**（含资源串行约束，连线时实时校验并提示）
- **舞台资源占用**：
  - 节点属性中填写资源名（如 `追光1`、`麦克风A`），支持已有资源名联想；留空表示不占用资源
  - 同一资源同一时刻只能服务一个提示：同资源节点**按画布节点（nodes）顺序自动串行**，
    无需手动连线，画布上以金色虚线 `🎚 资源名` 标出串行关系
  - 资源约束与显式依赖**共同参与正向 / 反向调度**
- **节点属性**：每个节点含 `持续时间`、`相对延迟`（全部前置约束满足后再等待的秒数；无前置时相对演出开始 T+0）与 `占用资源`
- **实时调度计算**：任一节点 / 连线 / 资源变更后，按「依赖 + 资源」约束图重算
  - 每个节点的最早触发 / 最早结束 / 最晚触发 / 松弛时间
  - 整场总时长与关键路径（红色高亮节点、依赖连线与资源串行虚线）
- **资源队列面板**：按资源列出每项提示的排程区间 `[T+起, T+止]` 与资源占用截止时刻，点击可定位节点
- **同步高亮**：
  - 关键路径在画布（节点描边发光 + 红色动画连线）与运行表（红色行）中同步标记
  - 画布 ↔ 运行表 / 资源队列双向选中联动
- **可排序运行表**：点击表头按名称 / 类型 / 资源 / 最早触发 / 持续 / 延迟 / 结束 / 最晚触发 / 松弛排序
- **JSON 导入 / 导出**：保留 `resource` 字段；兼容缺省资源的旧版文件；
  导入时校验类型、数值、引用完整性，以及依赖与资源串行合并后无环
- **辅助功能**：一键分层自动布局、小地图、Delete 键删除、示例演出预置

## 排练回放模式

点击工具栏 **▶ 排练回放** 进入（再点 **✎ 退出回放** 返回编排模式）：

- **按当前调度结果建立时间轴**：每个节点的触发 / 结束区间直接取自调度器的
  最早触发 / 最早结束时刻，**资源串行等待与显式依赖一律沿用**，回放不重新建模
- **演出时钟驱动**：播放时以演出时钟（T+0 = 演出开始）实时推进；时钟越过某节点
  触发时刻即产生一条 **🔔 到点提示**（控制条右侧滚动列出，最新高亮）
- **节点三态**：节点依次显示 **⏸ 待触发 / ▶ 进行中 / ✓ 已完成**（进行中绿色脉冲、
  已完成变暗）；运行表新增「回放」列、资源队列项显示状态点、小地图同步着色
- **暂停 / 继续 / 跳转必重算**：节点状态是当前时钟的纯函数，暂停后继续或
  **拖动时间轴**跳转都会整体重算全部节点状态
- **跳转不重复触发**：跳转时将时钟已越过的触发点全部登记为已触发，
  即使随后向后回退播放，已完成节点也不会再次弹到点提示
  （精确落在跳转目标时刻上的节点在该刻仍会正常触发）
- **重置回放**：⏹ 重置使时钟回到 T+0 并清空触发记录与提示列表；播到结尾后按 ▶ 自动从头重播
- **当前时间显示**：控制条以 `T+M:SS.s` 格式显示当前时钟与总时长，并汇总三态节点计数
- 回放模式下仍可编辑节点 / 连线 / 资源，时间轴与状态即时对账；导入 JSON 会自动停止并重置回放

> 回放状态仅为运行时状态，**不写入导出文件**；JSON 导入导出格式保持 v1 不变。

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

然后在浏览器访问 **http://localhost:8080**

> 端口映射为 `8080:80`（见 `docker-compose.yml`）。若 8080 被占用，
> 修改 ports 为如 `"9090:80"` 后访问对应端口即可。

停止：

```bash
docker compose down
```

也可以不使用 compose，直接用 Dockerfile 构建：

```bash
docker build -t cueflow .
docker run --rm -p 8080:80 cueflow
```

## 调度模型

**显式依赖**：连线 `A → B` 表示「B 依赖 A」。

**资源串行**：若 A、B 占用同一资源，且 A 在节点序列（nodes 顺序）中先于 B，
则隐含约束 `A → B`：B 最早只能在 A 结束后开始。资源串行链与显式依赖合并为
统一的约束图（合并图必须无环，否则连线 / 导入 / 资源编辑会被拒绝）。

正向传递（最早时刻）：

```
B.最早触发 = max(所有前置（依赖前驱 + 同资源前一项）的最早结束时刻) + B.相对延迟
B.最早结束 = B.最早触发 + B.持续时间
总时长     = max(所有节点的最早结束时刻)
```

反向传递求得各节点最晚触发时刻（资源约束同样参与），
`松弛 = 最晚触发 − 最早触发`；**松弛为 0 的节点构成关键路径**——
任何延误都会拉长整场演出。被「顶满」的显式依赖边与资源串行段均以红色标出。

> 示例：`追光1` 依次被「开场暖场光 → 追光定位 → 收场追光」占用，即使它们之间
> 没有全部直连，排程也会自动首尾相接，不发生重叠。

冲突提示：资源串行顺序由**节点顺序**决定（对应导入文件 `nodes` 数组顺序）。
若该顺序与显式依赖矛盾（例如依赖方向是后者 → 前者），系统会拒绝相应连线或
资源名修改并给出提示，保证合并约束图始终无环。

## JSON 文件格式（v1）

```json
{
  "version": 1,
  "nodes": [
    { "id": "n1", "type": "lighting", "label": "开场暖场光", "duration": 4, "delay": 0,
      "resource": "追光1",
      "position": { "x": 60, "y": 60 } }
  ],
  "edges": [
    { "id": "e-n1-n3", "source": "n1", "target": "n3" }
  ]
}
```

- `type`：`lighting` | `sound` | `actor`
- `duration` / `delay`：非负数值（秒）
- `resource`：可选，资源名字符串；**缺省、为 null 或空串时表示不占用资源**
  （旧版无此字段的文件可直接导入）。同名资源的节点按其在 `nodes` 数组中的先后顺序串行
- `position`：可选，缺省时自动摆放
- 示例文件见 [`examples/opening-night.json`](examples/opening-night.json)，可直接导入
